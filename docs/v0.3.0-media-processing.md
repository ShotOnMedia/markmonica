# v0.3.0 media processing foundation

The v0.3.0 media pipeline preserves every guest original and creates browser-friendly derivatives asynchronously in the worker.

## Current pipeline

- Uploaded originals remain unchanged in object storage.
- Existing and newly uploaded media start with `processing_status=pending`.
- The worker polls pending uploaded media and can also accept explicit `process_media` queue jobs.
- Images are EXIF-normalized and converted to a maximum 1600px WebP preview.
- Videos are transcoded with FFmpeg to H.264/AAC MP4 with `faststart` and a JPEG poster frame.
- Derivative object keys and processing state/error details are stored on the media row.
- Processing failures never delete or overwrite the original guest upload.

## Next steps

- Serve derivatives in the host gallery.
- Add processing-state UI/fallbacks.
- Queue processing immediately on upload confirmation in addition to resilient polling.
- Add automated tests for image/video processing metadata and failure handling.
